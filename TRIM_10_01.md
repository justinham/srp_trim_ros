# Workspace Trim — 2026-10-01

This document records the trim performed on `~/Downloads/ConnAu/` to reduce
the workspace from **1.9 GB to 38 MB** and isolate only the nodes needed
for the 6-node testing stack:

1. `ros2 run fusion Fusion`                           (EKF sensor fusion)
2. `ros2 run fusion_py SerialGPSReader`               (u-blox GPS via USB-ACM)
3. `ros2 run fusion_py CANGPSReader`                  (GPS via CAN bus)
4. `ros2 run fusion_py WpsFromJustinApp`              (planned waypoints from app)
5. `ros2 run fusion_py VehicleCommander`              (ROS → CAN bridge)
6. `ros2 run fusion_py VehicleCommanderSRP`           (trailer reverse-parking)

All other nodes remain in the workspace but are not built by `colcon build`
of the trimmed `fusion` and `fusion_py` packages.

---

## Why this trim was needed

The original workspace was cloned from the Hummer vehicle PC (Sept 23
backup). It contained:

- The full production stack (Fusion EKF + 3 controller versions + GTSAM
  factor-graph fusion + AAOS bridge + V2X OBU + collision avoidance).
- Several deprecated/legacy versions of files (multiple `WpsFromJustinApp`,
  multiple `ego_speed_test_node_ff`).
- Build artifacts (`.git/`, `build/`, `install/`, `log/`, run logs).
- MATLAB-generated C code for controllers that are NOT used by the 6-node
  testing stack.
- The GTSAM factor-graph fusion code that required a locally-built GTSAM
  library at `~/.local/gtsam-4.2/`.

For local development and unit testing of the 6-node stack, none of this
extra code is needed. Removing it makes the workspace:

- **~50× smaller** (1.9 GB → 38 MB)
- **Much faster to build** (~30 sec vs ~5-10 min)
- **Free of GTSAM dependency** (which was the build's most fragile step)
- **Easier to read** (fewer files = less cognitive overhead)

## Build + run sequence (Hummer Linux PC)

```bash
# 1. Source ROS2
source /opt/ros/humble/setup.bash

# 2. Go to workspace
cd ~/ConnAu/ros_ws

# 3. Build (now ~30 sec — was 5-10 min)
colcon build --symlink-install

# 4. Source the overlay
source install/setup.bash

# 5. Hardware setup (CAN bus + serial GPS)
sudo modprobe peak_usb peak_pci
sudo ip link set can0 up type can bitrate 500000
sudo stty -F /dev/ttyACM0 115200
sudo chmod 777 /dev/ttyACM0

# 6. Launch all 6 nodes in background
ros2 run fusion Fusion                                    > /tmp/fusion.log 2>&1 &
ros2 run fusion_py SerialGPSReader                        > /tmp/serial.log 2>&1 &
ros2 run fusion_py CANGPSReader --ros-args -p MY:=24     > /tmp/cangps.log 2>&1 &
ros2 run fusion_py WpsFromJustinApp                       > /tmp/wps.log 2>&1 &
ros2 run fusion_py VehicleCommander                       > /tmp/vehcmd.log 2>&1 &
ros2 run fusion_py VehicleCommanderSRP                    > /tmp/vehcmdsrp.log 2>&1 &

# 7. Watch logs
tail -f /tmp/*.log
```

## Open questions / follow-ups

1. **Trailer reverse-parking vs path tracking:** The 6-node stack does
   NOT include `ControlGen2` (the actual maneuver model that follows a
   planned path). `VehicleCommanderSRP` writes CAN frames directly,
   bypassing the maneuver model. This is intentional for SRP testing
   but means the Hummer in this config cannot follow a planned Bezier
   trajectory — only execute reverse-park maneuvers triggered by
   MQTT-tag-derived angles.

2. **GTSAM offline fusion:** If you want to do offline factor-graph
   fusion on recorded logs, you need to:
   - Re-add `object_factor_graph_fusion_node.cpp` (recover from Trash)
   - Re-add GTSAM dependency in CMakeLists.txt (currently commented)
   - Build GTSAM locally to `~/.local/gtsam-4.2/`

3. **Hardware dependencies for 6-node stack:**
   - PEAK PCAN-USB dongle for CAN bus (`can0` at 500 kbps)
   - GPS receiver on `/dev/ttyACM0` (u-blox F9P or compatible, 115200 baud)
   - MQTT broker at `192.168.5.51:1883` for `VehicleCommanderSRP`
   - DBC file at `/home/connau/ConnAu/DBC-ARXML/TrailerReverse_PoC.dbc`
     (path is hardcoded in `VehicleCommanderSRP.py` — symlink or patch)

4. **Mac compatibility:** None of these nodes will run on a Mac because:
   - No SocketCAN support (Linux kernel subsystem only)
   - No `/dev/ttyACM0` device
   - No PEAK PCAN driver
   - `ros2` is not installed (requires Linux)
   To develop on Mac, you'd need either Docker or a Linux VM with
   hardware passthrough.
